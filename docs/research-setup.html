Research workflow and ChatGPT connection

Implementation status

The app now implements evidence-packet assembly, structural/reference validation, saved research runs, feedback and linked revisions. A loopback helper implements Sign in with ChatGPT, account-specific model discovery and streamed structured inference. Automated tests use synthetic identities and model responses; real account sign-in, completed live inference and research usefulness still need acceptance testing.

There is no automatic web search, arbitrary code execution, outreach or promotion of model findings into the research pack. Optional model-planned public graph queries are validated and executed by browser JavaScript. A structurally valid output may still misinterpret a source. Review facts, citations, hypotheses and proposed investigations.

Start the local helper

On Windows, run start-research.cmd from the prepared app directory. It uses Node on PATH or the installed Codex bundled Node runtime if available. Otherwise install Node 24 from its official distribution. You can also run:

node tools/research-server.mjs

Keep that terminal running. Open http://127.0.0.1:8787, then select Research or a contextual action in any journey tab. If the port is occupied, set RESEARCH_PORT in the helper's environment before starting it. The helper binds only to 127.0.0.1 and serves an explicit public-asset allowlist, not the whole repository.

The helper origin and direct-file origin have separate browser storage. Existing file-based notes do not automatically move to the helper's browser workspace. Keep exports of existing work before changing origins.

Connect with OAuth

  1. Choose Connect ChatGPT, then follow Continue with ChatGPT in the sign-in tab.
  2. Select your account/workspace and decide whether to grant ChatGPT plan usage. Eligibility and workspace policy determine availability. An identity-only connection cannot run research.
  3. Return to the research tab and select Refresh connection. Confirm the connected account and plan status, then choose an available model.
  4. Use Disconnect before changing accounts. A saved registration can be selected when signing in again; Add a ChatGPT account creates another registration.

No API key is needed for this connection. It is a separate app registration; the helper does not extract Codex or browser login tokens. Sign-in uses fresh state, nonce and PKCE, verifies the ID-token signature/issuer/audience/expiry, and checks the actual granted plan scope.

Access, refresh and ID tokens never enter the static app, browser storage, source control or research export. Access/refresh tokens remain in helper memory only. Stopping the helper requires sign-in again. Non-secret host/client registration metadata and account labels are retained under .local/research-oauth/; that directory is ignored by Git and denied by the static server.

Disconnect attempts remote refresh-session revocation and clears the active local connection. If revocation cannot be confirmed, review the app's access in ChatGPT settings. Usage or eligibility failures are shown directly; the helper never falls back to API-key billing.

Choose a research starting point

Situation offers Investigate my assumptions; Next move offers Research this experiment; Startup offers Compare this example with my situation; Investor offers Research this investor. These open the same workspace with a question, selected records and captured context. The Research navigation item also opens the workspace directly. Inspect captured experiment/learning text as well as the selected source records before sending anything. See CONTEXTUAL_RESEARCH.md for source links and explicit plan acceptance.

Build and inspect a packet

  1. Set a startup profile in Explore investor fit. Saved company description and progress may also enter the packet; founder name, shortlist notes and drafts are not automatically selected.
  2. Enter a research question and select investor records and startup snapshots. Select at most five records in total; use Ctrl/Cmd for multiple selection.
  3. Choose the assessment date. An optional historical cutoff excludes sources whose publication/availability is unknown or later than the cutoff, and events after it. Current mandate scores, undated company narratives and prior model conclusions are omitted in historical mode.
  4. Optionally add a working finding with its URL and known publication date. It remains unverified, and does not update canonical investor facts.
  5. Select Build evidence packet, then expand Inspect prepared evidence packet. Inspect founder information, source dates, limitations, computed comparison results and disclosed omissions.

Contract version 1 allows five selected records, sixty evidence items, ten working findings, a 2000-character question and a 60,000-byte packet. Exceeding a limit produces an explicit error rather than silently discarding evidence. Partial publication dates are handled conservatively at the end of the known month/year for historical cutoffs.

Optional LLM graph exploration

  1. Build the packet, then open LLM graph exploration (optional). Inspect public graph catalog sent with the packet as well as the prepared packet. The catalog lists public node IDs, names and types that survive date boundaries; it excludes private contacts and fictional records.
  2. Connect ChatGPT, select an available model and check the consent box. Choose Plan and explore public graph. This sends the prepared packet and displayed catalog for one model planning pass.
  3. JavaScript validates the proposed queries and executes them in the browser. Supported queries are paths between existing public entities and same-round/shared-company network projections. Inspect the query audit, results, omissions and expanded packet.
  4. Consent resets. Check it again only after review, then choose Run research for a separate model request over the expanded packet. Planning and final reasoning may each consume plan allowance.

A successful planning pass allows at most three queries, four hops and five returned paths per query. Selected relationship evidence is limited to twenty edges; the expanded packet, including its query audit, must still fit 60,000 bytes. Invalid proposals, cancellation and overflow leave the original packet unchanged. Zero-query and no-path results are valid; they do not establish the absence of real-world relationships. Rebuild to change the question or repeat a successful planning pass.

Private contact graphs never enter this flow. The model cannot execute arbitrary code, change relationships or override deterministic investor eligibility. The final saved research run retains the expanded packet, query audit and available planner usage/model metadata. Exploration alone is not saved as a completed run; export the prepared prompt/packet if needed. See Relationships and introduction paths for graph interpretation and private-path rules.

Run, review and revise

Check the consent box only after inspecting the packet. Run research sends that packet to OpenAI using the selected ChatGPT connection and model. It can consume your plan allowance. The helper requests store:false and stream:true; this request setting is not a promise about every provider retention policy. No web search or arbitrary local execution tools are enabled; optional public graph planning is the bounded browser flow described above.

A run is accepted only after completed inference and structural/reference validation. Refusals, interrupted streams, usage failures and invented evidence references are visible errors and do not become saved research. Cancel request stops the browser request and aborts the helper's upstream inference when cancellation reaches it; already consumed usage is not undone.

Review the findings, interpretations, hypotheses, unknowns, contradictions, historical comparisons and proposed investigations. Source-reference validation checks IDs, not semantic support. Append feedback to the inspected run. Choose Use as previous revision, add a new finding if appropriate, rebuild/inspect the packet and explicitly request another run. Earlier outputs and feedback are retained.

History stores exact packets, captured source context, outputs, model/prompt identifiers, available usage data and revision links in a separate browser key by provider/pack identity. It has a local size limit and never silently deletes older runs. Export research history creates a private JSON backup. There is no import interface. A failed save is shown explicitly; export any unsaved inspected run before closing the tab.

Direct-file/manual mode

Opening index.html directly still works without the helper. Build a packet, expand Use another model manually, and export its prompt/evidence text. Sharing that file with a model is your separate decision. Paste the structured JSON response, supply the model/method label and select Validate and save response. Manual metadata is user-supplied, not independently attested. Never paste OAuth credentials into these fields.

Acceptance and evaluation

Before treating live research as validated, complete actual OAuth sign-in, model discovery, one completed public-data run, optional graph planning followed by a separately consented final answer, cancellation/error handling and a revision with feedback/new evidence. Then use the reviewer gates in RESEARCH_PLAN.md: citation support, unsupported assertions, historical leakage, contradictions, actionability, revision quality, usage and latency. Compare with deterministic guidance and a plain evidence summary.

The current automated tests establish packet boundaries, reference integrity, signed-token handling and synthetic helper behavior. They do not establish model quality or account/workspace availability. LOCAL_RELEASE.md tracks the remaining acceptance and founder pilot.

Official protocol references

Registration and sign-in, accounts and sessions, models and inference, and preview limitations define the OAuth and plan-usage request contract. Availability can change; consult those references when diagnosing a real connection failure.
